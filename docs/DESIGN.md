# CUI 设计说明（v0.11）

## 1. 要解决的问题

写基岩版 JSON UI 的最大成本是**验证**：排版规则不直观（`keep_ratio` 缺省 true、`anchor_from` 是父控件上的点…），动态效果全靠
字符串形式的绑定表达式，任何错误都要进游戏才看得到。GuideBook 开发里连续几轮「改了没用」都出在这里。

CUI 的做法：**一棵对象树，三个出口**——

```
对象树（new Panel({...}).add(...)；自定义组件 = 子类）
   │ finalize()：拍成快照，给没写名字的元素分配确定的名字；Pages 等在此时收尾
   ▼
控件树 RNode ──► 编译器 compileNamespace() ──► JSON UI 命名空间文件（+ 静态检查）
   │
   └──► 排版引擎 layout()（纯函数）──► 浏览器预览 mountPreview()、单元测试
```

## 2. 分层与借鉴

| 层 | 文件 | 借鉴 | 说明 |
|---|---|---|---|
| 对象模型 | `core/element.ts` | Qt / Android View、你的原型 | **纯面向对象**：元素是类的实例，参数是普通对象，`add()` / `set()` / `clone()`；自定义组件 = 子类。没有标签、没有虚拟树包装函数 |
| 表达式 | `core/expr.ts` | Vue / Solid 的 computed；AsaJS 的表达式编译 | 带类型的构造器 → AST → ① 编译成 JSON UI 字符串 ② 预览里按 JSON UI 语义求值（字符串 `-` 去掉所有出现等） |
| 响应式 | `core/reactivity.ts` | Solid 的信号（原型保留） | **只在预览端用**：游戏界面里没有 JS，动态行为全部编译成绑定 |
| 排版 | `layout/units.ts`、`layout/engine.ts` | Yoga（React Native） | 纯函数实现 JSON UI 的排版规则，预览与单测共用 |
| 编译 | `mc/compile.ts` | mcbe-ts-ui、AsaJS | 确定命名；动态属性自动生成绑定；FormButton 用 sapdon 真机验证过的写法 |
| 检查 | `mc/lint.ts` | ESLint | 规则来自 sapdon `known-pitfalls.md` |
| 预览 | `web/index.ts` | Storybook；JsonForge 的画布 | 绝对定位画引擎算出的矩形；悬停 / 按下；开发面板 |

与现有项目的区别：AsaJS、mcbe-ts-ui 是 JSON UI 生成器，没有预览；JsonForge 是可视化编辑器。
CUI 的核心是「**对象模型 + 按游戏规则的预览 + 规则可测试**」。

### 开关分页（Pages，v0.3）

整本书放在一个表单里，翻页由客户端的单选开关完成（继承原版 `common.toggle`：`toggle_name` + `radio_toggle_group` +
`toggle_group_forced_index`），不关表单、不重开——GuideBook「翻页时视角偏转」的根因（两个表单之间的空档）随之消失。

- 每页 `visible` = 「任意一个指向本页的开关被选中」（`toggleState(a) or toggleState(b) …`）。单选组任一时刻只有一个开关选中，
  所以无论引擎会不会把同序号的开关一起选中，结果都对；每页有一个零尺寸锚点开关承载初始选中。
- 别的控件按**开关名**读状态（`source_control_name`，原版 `light_ui_toggle` 就是把开关控件命名为 `$toggle_view_binding_name`），
  所以开关名必须全局唯一（lint）；跨区域读取不写 `resolve_sibling_scope`（原版主界面标签页的写法）。
- 第二个 `Pages`（不同 group）= 独立状态：物品详情做成弹层，关掉后回到原来那页，不需要「历史记录」。
- 运行期数据仍来自表单：正文（`form.text`）与按钮文字（`CollectionItem` 里的 `form.buttonText`）。

### 真机确定的模式（测试包 1.0.0 – 1.0.2）

| 场景 | 做法 | 原因 |
|---|---|---|
| 读开关状态 | `toggleState(名字)`，不加 siblingScope | 缺省全局查找；加 `resolve_sibling_scope` 反而只找兄弟控件 |
| 一页有多个入口 | 每页 visible = 所有指向它的开关的「或」（Pages 自动生成） | 同序号的开关不会一起选中，只有被点的那个选中 |
| 弹层 | 第二个 Pages（独立组）＋ `pages.blocker(弹层所在页)`：透明、无声、指向弹层自己那一页的开关 | 弹层下面的开关能被点穿；拦截层层级更高、先接住点击；点它不改变状态，只有「关闭」才关 |
| 开关里显示表单按钮数据（物品格子悬停提示框） | 把 `CollectionItem` 放进开关的**状态面板里** | 开关内部读不到外层集合项的数据（common.toggle 的绑定遮住上下文）；lint：`collection-through-toggle` |

## 3. 已实现的 JSON UI 规则（排版引擎）

依据：Bedrock Wiki · JSON UI Documentation，以及 sapdon / GuideBook 的真机结论。

- 位置 = 父矩形上的 `anchor_from` 点 + `offset` − 自身的 `anchor_to` 点；缺省 center；百分比偏移相对父控件。
- 尺寸：像素；`%`；`%c`（stack 沿方向求和，其余取最大）；`%cm`；`%x` / `%y`；`fill`（stack 里平分剩余）；`default`（label = 文字尺寸，其它 = 100%）；混合表达式 `'100% - 2px'`。
- stack：沿方向依次摆放，交叉方向按锚点；`visible=false` 的子控件不占位。
- grid：格子 = 网格尺寸 / 行列数；`gridPos` 落格。
- layer 相对父控件累加；`clips_children` 裁剪子孙。
- image：`keep_ratio` 缺省 **true**，按贴图比例缩小居中；九宫格贴图直接拉伸。
- label：中文 8 像素、中文窄标点 3、ASCII 按 Minecraft 字宽表，行高 10；宽度确定时折行。

## 4.0 长文本与富文本（v0.4）

- **格式码按基岩版**（`font/rich.ts`）：颜色 §0–§f ＋ 基岩版独有 §g（硬币金）与材料色 §h §i §j §m §n §p §q §s §t §u §v（§m / §n 是颜色，
  基岩版没有删除线 / 下划线）；§k 乱码、§l 粗体、§o 斜体、§r 重置；**换颜色不清掉粗体 / 斜体**（Java 版会清）。
- **两种折行**：
  - 静态文字用 `Paragraph` / `wrapText()` **预折行**：按字宽表、避头尾、中英文留空（中文标点后接英文也留，英文后接中文标点不留），
    **每行开头补上延续的样式码**，行宽留 8 像素给挂在行尾的标点 ⇒ 引擎不会再折一次，结果确定。
  - 运行期文字（表单正文、按钮文字）长度事先不知道：交给引擎折行（宽度固定、高度 default）。
- **分页** `paginate()`：预折行后按每页行数切块；孤行控制——页末是段落首行（标题、或段落只剩首行）就挪到下一页，页末不留空行。
- **静态检查** `text-overflow`：宽高都固定的文字框放不下静态文字。

### 字体与字宽（真机字宽标尺逐像素校准，测试包 1.1.0）

- **整段文字的字体由内容决定**：含任何非 ASCII 字符（汉字、中文标点……）⇒ 整段都用 **GNU Unifont** 点阵画（连其中的英文、数字、空格）；
  纯 ASCII ⇒ Minecraft 默认字体。真机：「Esc 关闭」里 E、s、c 的字距是 4（Unifont），纯英文行里是 6。
- Minecraft 字体：! ' , . : ; i | 2，l ` 3，I t [ ] 空格 4，f k < > ( ) { } " * 5，~ 7，其余 6（含 @）；粗体每字 +1。
- Unifont：字距 = 点阵墨迹宽 / 2 + 1（半像素精度，与 Java 版 unicode 字体同规则）；绝大多数汉字 8.5（约 1.76 万字）、8.0（约 2600），
  「中」6.5；中文逗号 2、句号 3、空格 4；粗体每字 +0.5。逐字位置与真机误差 < 0.5 像素。宽度表由 `scripts/gen-unifont-widths.mjs` 生成。
- 更正：早先的「汉字 8、窄标点 3」是从截图粗估的，对大多数汉字偏小 0.5、对窄字偏大。

### 静态界面为缺省，路由界面为可选（v0.11）

真机 1.13.0 响应式演示的**屏幕标尺**显示：标尺原点不在屏幕左上角，而和卡片中心几乎重合——演示的根面板（路由界面里的 100%）在游戏里**接近 0×0**，
百分比尺寸全成了 0，卡片一直被最小尺寸托住，所以窗口怎么变都一样（静态的测试书则正常铺满居中）。加上 1.10.0 / 1.12.0 的默认聚焦问题，
路由界面已两次与静态界面表现不同 ⇒ `serverForm` 的界面**缺省为静态**，路由要显式写 `routed: true`（只在界面用固定像素尺寸、不靠默认聚焦时用；
@bedrock-core 的界面是固定 320×210 画布，所以不受路由单元尺寸影响）。没有路由界面时不生成路由。静态界面的 id 不能是别的标题的一部分（构建时检查）。

### 静态界面与路由界面（v0.10）

真机 1.10.0：测试书改成路由界面（路由变体）后**能显示**，但鼠标不动连点「下一页」会**乱跳**——聊天栏里在钻石剑页收到 11（上一页）、在钻石页收到 13（上一页）、
最后收到 4（×）。1.5.4 的静态写法同样的箭头 / 聚焦优先级是可靠的。推断：路由界面由工厂在表单打开**之后**才创建，游戏决定默认聚焦时箭头还不存在
（1.9.0 路由界面里读正文的页码开关也不生效，同样指向「工厂创建的控件，绑定与聚焦的时机不同」）。

所以 `serverForm` 的界面分两种：
- **静态界面**（`routed: false`）：表单打开时就创建，按「标题包含 panelId」显示，绑定不加 always——与 1.5.4 完全相同。要靠默认聚焦连点翻页的界面（测试书 / 指导书）用它，
  分页用 `pages.useServerPages()`：标题 `<id>|P:<页名>;`（`pages.titleFor()`）+ 服务端锚点 + 页码开关。
- **路由界面**（缺省）：只在打开它时创建（工厂 + 标题路由），绑定加 always。不依赖默认聚焦的界面用它（响应式演示等）。分页可用 `useRoutePages()` + `serverRoutes()`
  （标题 `<id>/<页名>`），但默认聚焦不可靠。⏳ 1.11.0「路由版翻页实验」（指南针）与静态的测试书对照，确认是不是路由导致的。

**真机 1.12.0 三方对照（已有结论）**：书（静态界面）鼠标不动连点**完全正常**；指南针（路由界面）**乱跳**——证实路由界面的默认聚焦不可靠；
时钟（路由界面 + 「焦点交接」：静态部分放 1×1 透明缓冲按钮，优先级 1000，界面建好后隐藏它）——点击有按钮声但不在箭头上，要动鼠标才行：
**缓冲按钮隐藏后游戏不会重选焦点**，交接无效（已从框架移除，实验也撤掉）。结论：**靠默认聚焦连点翻页的界面一律用静态界面**；路由界面用于不翻页的界面。

### 服务端分页 = 路由变体（v0.9，现为路由界面专用）

真机 1.9.0：改成按标题路由后，旧的「服务端锚点 + 读正文的页码开关」不生效——书打开一片空白、翻页箭头也进空白页（目录 / 书签这些客户端开关正常）。
新做法完全不需要锚点与页码开关：**每一页一个路由**。标题 `<界面 id>/<页名>`（`serverTitle()`）路由到「同一个界面 + 一个变量」的派生元素
（`screen_0_sword@ns.screen_0: { $toggle_group_default_selected: 1 }`）；这组开关不写死初始选中序号（原版 common.toggle 用 `|default` 声明，
会继承祖先设的值），所以表单打开时那一页的开关**本来就是选中的**，页面显示条件只读开关状态（1.4.0 起真机一直正常的写法）。
`new Pages('gbp').useServerPages()` + `serverForm({ panels: [{ panelId, content, routes: pages.serverRoutes() }] })`。⏳ 1.10.0 待真机确认。

### 混合翻页（Pages 的 server 模式，v0.6–v0.8 的旧做法，已废弃）

真机结论：开关翻页（客户端）切换即时，但游戏只在鼠标移动时重判光标下的控件——鼠标不动连点翻页箭头没反应（A / B / C 三种开关方案都不行）；
服务端翻页（关表单、服务端重开下一页）鼠标不动也能连点。所以：

- **翻页箭头 = FormButton**：每个箭头一个表单按钮序号，脚本按「序号 → 目标页」表重开表单，标题带 `P:<页>;`；
- **目录、书签、详情弹层 = 开关**（即时，不经服务端）；
- `new Pages({ …, server: {} })`：加一个隐藏的「服务端锚点」开关（序号 = 页数，初始选中）。⚠️ 不能用 -1：`toggle_group_forced_index` 缺省就是 -1，表示「不强制、按顺序自动分配」——真机 1.5.0 用了 -1，单选组乱掉、进不了任何子页面。lint：`toggle-index`。锚点选中时按标题里的页码显示（没有页码 = 初始页）；
  用户点了任何翻页开关，锚点不再选中，改由开关接管。全部是 JSON UI 表达式：`页面 visible = 任一指向它的开关选中 or (锚点选中 and 标题含 P:<页>;)`。
- 「标题里是不是这一页」放进每页一个**页码开关**（`stateFrom`：只读标题，写进自己的 #toggle_state），页面显示条件**只读开关状态**：
  `任一入口开关选中 or (服务端锚点选中 and 本页页码开关选中)`。真机 1.5.2：一条表达式同时读开关状态与全局绑定（#title_text）时，
  **开关变化不会触发重新计算**（目录行已选中、锚点已取消，页面却不切换）。lint：`mixed-sources`。
- **默认聚焦**：真机 1.5.2——服务端重开表单后鼠标没动，点击交给**默认聚焦**的控件（日志：翻页后下一次点击收到的是右上角 × 的序号 4，书就关了）。
  每个翻页箭头两个同序号的表单按钮：普通版（聚焦优先级 10）+ 聚焦版（文字带 F 才显示，优先级 100）；脚本给新页面上「刚才点击方向」的箭头加 F。
- **「原地不动」按钮**：透明的表单按钮，聚焦优先级 50（介于聚焦版箭头 100 与普通箭头 10 之间）。当前方向没有箭头时（最后一页再点「下一页」），
  鼠标没动的点击交给它，服务端原样重开当前页——真机 1.5.3：否则落到反方向的箭头，在最后两页之间来回循环。
- **脚本总是在标题里带页码**（第一次打开也带 `P:<起始页>;`）。起始页的页码开关另有「没有页码也算」的兜底，写成 `(标题 − 'P:') = 标题`，
  不写 `not (not …)`——真机 1.5.3：带双重否定时，翻回目录（`P:home;`）一片空白。
- 书打开期间锁视角（表单之间的空档）；serverForm 缺省去掉屏幕进出场动画（1.5.2 两个变体对照：与目录失灵无关）。

### 面向对象的 API（v0.8）

构造函数只收必要参数，其余属性用有类型的读写属性或链式方法设置；值是有类型的不可变对象（`src/core/values.ts`）：

| 值类型 | 用途 | 例子 |
|---|---|---|
| `Length` | 一个方向上的长度，可加减 | `Length.pct(100).minus(6)`、`Length.children().plus(8)`、`Length.fill()` |
| `Size` / `Vec2` | 尺寸 / 偏移 | `Size.of(Length.pct(90), 40)`、`Size.full()`、`Size.fitContent(4)` |
| `Anchor` | 锚点 | `Anchor.CENTER_LEFT`；`setPlacement(Anchor.TOP_RIGHT, Anchor.TOP_LEFT)` = 贴在父控件右边外侧 |
| `Color` / `Insets` | 颜色 / 内边距 | `Color.hex('#3d2108')`、`Insets.symmetric(3, 0)` |
| `Texture` | 贴图 + 尺寸 / 九宫格信息（跟着贴图走，静态检查与预览直接查，不再另维护信息表） | `Texture.of('textures/ui/cell_image').withSize(10, 10).withBaseSize(5, 5).withNineslice(1)` |
| `TextStyle` | 文字样式，不可变、可共用 | `TextStyle.of(Color.WHITE).withShadow().withScale(0.8)` |

元素：`new Label(文字, 样式)`、`new Image(贴图)`、`new Toggle(组, 序号)`、`new FormButton(序号, 标记, 宽, 高)`、`new Pages(组).startAt('home').useServerPages()`、
`new Paragraph(文字, 宽, 样式)`；属性 `el.size`、`el.offset`、`el.layer`、`el.visible`、`el.padding`… 读出来是值对象；链式 `setSize / setOffset / setAnchor /
setPlacement / setLayer / setVisible / setPadding / setMinSize / setMaxSize / setGrow …`。自定义组件 = 继承（`class StatRow extends Row`）。
旧写法（构造函数传一个参数对象）仍能编译，但已标 `@deprecated`；内部表示（props → RNode → 编译器 / 排版引擎）不变，新旧写法编译结果逐字节相同（测试）。

### 弹性布局与响应式（Row / Column）

`Row`（横排）/ `Column`（竖排）：`setGap`、`setJustify(START | CENTER | END | SPACE_BETWEEN)`、`setAlign(START | CENTER | END | STRETCH)`；子控件 `setGrow()` 平分剩余空间、
`setMinSize / setMaxSize` 上下限。快照时展开成 JSON UI 原生结构：`stack_panel` + 每个子控件一个**槽位**面板（主轴尺寸取子控件的：伸展 = fill、按内容 = 100%c、像素原样）+ 间距 / 分布用的占位面板（fill）。
交叉轴 STRETCH 只拉伸**没写尺寸**的子控件（同 CSS），文字因此按列宽折行。容器按内容定尺寸时：主轴 100%c、交叉轴 100%cm（stack 的 %c 两个方向都是求和——真机）。

**响应式 = 运行时自适应**：尺寸写百分比 / fill，再用 `min_size / max_size` 给上下限，游戏按实际屏幕算——不是在固定画布上预先算死坐标（@bedrock-core 的 flexbox 是 320×210 固定画布）。
预览 `preview.resize(w, h)` 切换屏幕尺寸（`?demo=responsive`：小屏手机 320×180、手机 480×216、电脑 640×360）。⏳ 1.9.0 测试包「响应式演示」（手持纸右键）待真机确认 min_size / max_size 与这套结构。
JSON UI 没有可靠的屏幕尺寸信号，「断点」（窄屏换一种布局）目前做不到；能做的是流式布局 + 上下限。

### 滚动区域（Scroll）与「放不下」检查

`new Scroll()`：子控件竖排（同 Column），内容高度按子控件之和，超出部分滚动。编译成原版 `common.scrolling_panel`：内容提升为命名空间顶层元素，
`$scrolling_content` 引用；滚动条在区域内侧（宽 8）。预览：鼠标滚轮滚动、画滚动条。
真机 1.9.0 响应式演示：窗口很小时卡片被最小尺寸托住，右栏文字折成 7 行，合成材料压到了底栏按钮上 ⇒ 会变长的内容放进 Scroll。
lint `flex-overflow`：在 400×300 与极小的 240×135 两种屏幕上排一遍，Row / Column 里的内容沿主轴放不下就警告（复现了 1.9.0 的重叠：超出 29 像素）。

**在游戏里看响应式**（真机 1.10.0 的观察）：基岩版**按窗口大小自动选界面缩放**，拖窗口时界面像素数大致不变，整个画面只是等比缩放；
真正改变界面像素数的是**长宽比**（带鱼屏更宽）与「视频设置 → 界面缩放」。1.10.0 的演示上限 400×250 在常见电脑屏幕上一直顶着，所以只看到整体缩放 ⇒
上限放宽到 560×320，并加了**屏幕标尺**（上边、左边每 50 界面像素一个刻度，屏幕边缘露出的最后一个数字 ≈ 屏幕尺寸）。
滚动条：原版 scrolling_panel 的滚动条**盖在内容上面**（真机 1.10.0：文字被挡住）⇒ 滚动内容宽 100% − 8px。

### 只创建需要的界面（标题路由）

serverForm：根面板（按前缀显示）里一个带工厂的 `collection_panel`，属性包 `#route_<标题>` = [界面 id]；绑定 `('#route_' + #title_text)` 求出属性名，引擎读它的值写进
`#collection_length`，工厂只实例化那一个界面（与 @bedrock-core/ui 的表单路由同一机制）。每个界面是命名空间里的独立元素 `screen_<n>`。
**标题必须与 panelId 完全相同**：页码等放进表单正文（`Pages.useServerPages()` 缺省读正文）。所有绑定都带 `binding_condition: 'always'`（工厂创建控件后数据才到）。
⏳ 1.8.0 / 1.9.0 测试包待真机确认。

### 为什么原生界面能连点、JSON UI 客户端翻页不能；DDUI

原生界面（书与笔的翻页箭头）里，箭头**始终是同一个控件**，翻页时由游戏的界面控制器（C++）改写内容。JSON UI 附加包没有逻辑能改写
一个控件的行为：单选开关只能「跳到第 N 页」，每页的「下一页」必然是不同的控件——光标下的控件换了，游戏要等鼠标移动才重新判定。
A / B / C / E 五种客户端方案都不行；服务端重开表单（新屏幕、按默认聚焦）可以，这就是混合翻页。

**数据驱动界面（DDUI）**：`@minecraft/server-ui` 2.2.0 稳定版（真机所用版本）已有 `CustomForm` + `ObservableString / Boolean / Number`。
按钮 `button(文字, onClick, { disabled, tooltip, visible })` **不关表单**，回调里改可观察数据，界面即时更新——「下一页」一直是同一个控件，
与原生界面同一个道理。另有 header / label / image（可点击、带提示框）/ toggle / slider / dropdown / textField / divider / spacer。
限制：由 Ore UI 画，**不能用 JSON UI 改造**；布局是从上到下的一列；外观（颜色、九宫格底图、边距的 styleId）要到 1.26.60 预览版才开始支持。
测试包有「DDUI 翻页实验」（1.10.0 起羽毛右键 / scriptevent cui:ddui；1.9.0 用书与笔触发时原版书写界面会先打开）。真机 1.9.0：外观不错、翻页可用，但翻页瞬间内容闪一下（一次翻页改 6 个可观察数据，换图片要重新加载）⇒ 1.10.0「对照版」（燧石 / cui:ddui2）：每页的标题 / 图片 / 正文预先建好，翻页只切换显示。真机 1.10.0：两个版本都有时「框的高度变一下」，多翻几次后消失 ⇒ 原因是各页正文长短不同、表单高度本来就随页变化（对照版先显示新页再隐藏旧页，还有一瞬间两页同时显示）；1.11.0 各页正文补齐成相同行数、对照版先隐藏再显示。用户补充：最终三页高度一样，只是翻页时有概率「缩一下」，多翻几次就不再出现 ⇒ 更像是**图片第一次显示时贴图还没加载、高度暂为 0**；1.12.0 表单打开时把三张图预先显示（预加载）→ 真机：两个版本都**不再缩**，确认是图片首次加载；但 `width: 1` 没把图缩小，图整个显示了出来。1.13.0 找「看不见的预加载」：羽毛 = 预加载图一开始就隐藏 → 仍常闪；燧石 = 先显示 10 tick 后隐藏 → 偶尔闪（隐藏后贴图可能被释放）。查 API：**image 的 width 是「占表单宽度的比例」**（1 = 满宽；>1 或 ≤0 当作 1）——1.12.0 的 1 就是满宽，正式图片写的 32 也被当成满宽；2.2.0 没有任何位置 / 高度 / 边距设置，放到屏幕外或固定高度占位都做不到 ⇒ 1.14.0：预加载图 width 0.01（两三个像素）**一直显示**在底部，正式图片 width 0.15。CUI 的组件树与后端解耦，DDUI 可作为第二个后端（路线图）。

### 安全区（padding / contain）

JSON UI 没有内边距。CUI 的 `padding`（数字或 [左, 上, 右, 下]）编译成一个内层内容面板（尺寸 100% − 两边、偏移 = 左上）；
`contain: true` 声明「子孙不得越出」，lint 按排版结果检查（`out-of-bounds`，所有页面都排出来）；提示框这类有意越界的写 `overflow: true`。

### stack 的 %c（真机，提示框过宽）

stack_panel 的 `%c` 在**两个方向上都是子控件之和**——交叉方向也求和（提示框 = 两行宽度之和 + 8，实测 86 = 25 + 53 + 8）。
要贴合最宽 / 最高的子控件用 `%cm`。lint：`stack-cross-c`。

## 4.1 预览精度：哪些和游戏一致、哪些是近似

| 内容 | 状态 |
|---|---|
| 位置、尺寸、图层、裁剪、keep_ratio | 按排版引擎（规则见 §3） |
| 九宫格 | 按贴图 `.json`：`nineslice_size` 的单位是 `base_size` 的格。原版 `cell_image.png` 是 10×10 像素、`base_size` 5×5 ⇒ 切贴图 2 像素、画到界面 1 像素（v0.3.1 之前只切 1 像素，格子边框画错）。切片覆盖整张贴图（`highlight_slot` 1×1）时按整张拉伸 |
| 贴图信息 | 用 `cui/node` 的 `textureInfoFrom([资源包目录…])` 直接读 PNG 宽高与同名 `.json`，不要手抄 |
| 文字位置 | **逐字定位**：每个字占的宽度严格按字宽表（与排版引擎一致），所以预览里的折行位置、文字长度就是引擎算的 |
| 文字字形 | **像素字体**（`mountPreview({ fonts })`）：含非 ASCII 的文字用 Unifont 点阵（半像素）、纯 ASCII 用 Minecraft 默认字体 ascii.png——与游戏同一套字形；阴影、粗体、斜体、§k 照游戏的画法。字体文件由 `scripts/fetch-fonts.mjs` 准备（ascii.png 取自本机 Java 版客户端，不随源码分发）；没有时退回系统字体 |
| 字宽表本身 | ✅ 真机逐像素校准（ASCII 表、Unifont 规则、粗体 +1 / +0.5、斜体不变宽） |

## 5. 静态检查规则

| 规则 | 级别 | 出处 |
|---|---|---|
| `keep-ratio`：贴图会被按比例缩小居中（缺省 keep_ratio） | 警告 | known-pitfalls §4.20 |
| `collection-index`：不是合法属性 | 错误 | sapdon-ui.md §7.3 |
| `collection-ref-outside`：在 FormButton 外读 `#form_button_text` | 错误 | — |
| `collection-item-size`：集合项要写像素尺寸 | 警告 | known-pitfalls §4.20 的弯路 |
| `collection-through-toggle`：开关里读外层集合项的数据 | 错误 | 测试包 1.0.1 |
| `toggle-name-unique`：开关名全局唯一 | 错误 | 开关按名字全局查找 |
| `toggle-index`：开关序号必须是非负整数 | 错误 | 1.5.0（-1 = 自动分配，撞号） |
| `mixed-sources`：一条表达式同时读开关状态与全局绑定 | 警告 | 1.5.2（开关变化不触发重算） |
| `obfuscated-unifont`：§k 出现在含汉字的文字里 | 警告 | 1.5.3（只显示成点） |
| `grow-outside-flex`：setGrow() 写在非 Row / Column 的子元素上 | 警告 | 不起作用 |
| `flex-overflow`：Row / Column 的内容在某种屏幕尺寸下放不下 | 警告 | 1.9.0 响应式演示重叠 |
| `scroll-in-collection`：Scroll 放在集合项里（内容提升到顶层，读不到集合数据） | 警告 | 结构限制 |
| `text-overflow`：固定高度的文字框放不下 | 警告 | — |
| `stack-cross-c`：stack 交叉方向写 %c | 警告 | 1.1.0 提示框过宽 |
| `out-of-bounds`：contain 元素里越出安全区（按排版结果，所有页面都排出来检查；overflow: true 的跳过） | 警告 | 1.2.0 刻度尺伸出书页 |
| `duplicate-name`、`bad-size` | 错误 | — |

## 6. 已知限制与路线图

1. 混合翻页（1.5.0）真机确认后，用它复刻 GuideBook。
2. 模板与引用（`name@namespace.base`、变量覆盖），对原版界面的 `modifications`。`serverForm({ panels })` 已支持一个命名空间里放多个按标题区分的界面。
3. factory / 通用集合、scroll_view、文本输入、动画（anim_type）的类型化写法。
4. sapdon 适配器：写文件、维护 `_ui_defs.json`、挂到 server_form 的标题门控。
5. 其它后端：DDUI（server-ui 2.2.0 稳定版已有 CustomForm + Observable，翻页按钮可以是同一个控件；外观受 Ore UI 限制）、Ore UI——JSON UI 已在弃用路线上，组件树与后端解耦就是为此准备。
   构建测试包时用 TypeScript 按官方类型定义检查生成的脚本（`CUI_MC_TYPES`）；`node --check` 对未闭合的字符串也返回 0，不可靠。
6. 用 CUI 复刻 GuideBook（开关分页 + 物品详情弹层），作为第一个完整的验收对象。
