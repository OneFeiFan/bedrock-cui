# 手册写作约定

以 [Vue 中文文档](https://cn.vuejs.org/guide/introduction) 的笔调为准，编排参考 [react.dev](https://react.dev/learn)。拿不准时，对照 Vue 中文文档里对应主题的页面。

## 结构

- **指南**（`guide/`）按章节递进，后一页只用到前面介绍过的内容。只介绍常用用法，完整的选项链接到参考。
- **参考**（`reference/`）按模块逐条列出 API：签名、参数、返回值、示例，不讲背景。

一页的结构：

```md
# 标题

一句话说明本节的内容（可省略）。

## 小节标题

概念说明 → 示例代码 → 对示例的说明。
```

页面之间的导航由网站每页底部的「上一页 / 下一页」负责，正文中不写「下一步」一节。

## 笔调

主语是 API、框架或游戏，不是读者：

| 不这样写 | 这样写 |
|---|---|
| 你可以用 `Paragraph` 让文字按宽度折行。 | `Paragraph` 按给定的宽度折行。 |
| 你会注意到两件事。 | 上面的示例展示了两点。 |
| 这一页带你从空文件夹走到…… | 本节演示从创建项目到……的流程。 |
| 点一下箭头，表单会关掉。 | 点击箭头时，表单关闭。 |
| 给控件起名字是个好习惯。 | 建议为需要定位的控件设置名称。 |
| 直接写 JSON UI 是一件费劲的事。 | （删去。只陈述框架做什么。） |

- 「你」只用于指示和建议：「你不应在……时……」「应提交到版本库」。
- 不写关于文档本身的话（「下面马上会用到」「你已经学会了」），不评价、不安慰、不推销（「强大」「轻松」「逐像素」「好消息是」）。
- 用书面语：「此」「该」「将」「即」「可」；不用「就是」「其实」「当然」「一下」「啦」。
- 机制用技术语言讲清楚：「游戏在同一层内按材质分批绘制，先在控件树中出现的批次先绘制。」
- 能写进代码注释的说明，写在注释里。
- 标题用名词短语：「挂载到服务端表单」「服务端翻页」「静态检查」，不用「读懂检查的提示」这类对读者说的话。
- 加粗只用于列表项开头的术语，正文里不加粗。

## 读得懂

1. **先讲机制，再讲用法**。依赖外部系统（游戏、服务端表单）的功能，先说明外部系统原本的样子与特性，再说明框架怎样利用它。没有这一层，后面的 API 都成了谜语。
2. **术语先定义，再使用**，并说明是框架规定的含义还是通用含义（「界面」「界面 id」「页」）。定义集中放在一处，其他页面链接过去。
3. **一段只有一个主语**。主语切换时换段，并点名新的主语（「`Paragraph` 的 `setWrap('hard')` ……」），不要在讲属性的段落里突然让一个方法成为主语。
4. **每提到一个方法，写明由谁调用、参数与效果，并配代码**。正文中统一写作 `对象.方法(参数)`；不用无参数的 `add()` 泛指有参数的方法。
5. **注明 API 的归属**：游戏的脚本 API（`ActionFormData`、`player.sendMessage()`）与框架的 API 第一次出现时写明属于谁。
6. **不写无法按字面理解的句子**。反例：「按钮的文字不一定显示为按钮」「脚本传给表单的内容，就是界面可以读取的数据」（哪个脚本？哪个界面？）。
7. **写明默认值**（「`Paragraph` 默认软换行」）。
8. **示例中的模拟数据要说明它代表什么**（「示例中的 `data` 模拟脚本打开表单时传入的内容，只用于预览」）。
9. **标记新增的代码行，优先在行末写 `// ← 新增`**，不依赖行号；行号高亮已出过两次错。
10. **写给作者或贡献者的话不放进使用者的文档**（「发布到 npm 之前先全局安装」→ CONTRIBUTING）。
11. **读者测试**：以没有参与开发的读者视角通读，对每一句问：主语是谁？宾语指什么？这个词在哪里定义过？这个方法由谁调用、传什么？

## 验证的程度

- 真机验证过的写「（真机）」；未验证的明说「尚未验证」「待真机确认」，不写成定论。
- 写进文档的输出（例如静态检查的提示）先实际运行一次再抄。
- 网站的替代贴图要模仿原版的样子（原版 `textures/ui/white` 带黑边），否则预览会掩盖问题。

## 示例

- 在线示例：`preview=变量 宽x高`；学习章节代码优先、组件页预览优先；`vary=变量:最小-最大` 加参数滑块（代码中写 `const 变量 = 数字`）。
- 承接上文、不能单独运行的片段以 `// 接上例` 开头。

- 示例只包含说明当前主题所需的代码，省略的部分写 `// ……`。
- 在上一段代码的基础上修改时，用 ` ```js {3-4} ` 标出新增或修改的行（网站上显示为绿色背景，并自动加一行说明）。修改示例后要重新核对行号。
- 需要在网站上实时预览时，写成 ` ```js preview=变量名 宽x高 `：代码只能从 `bedrock-cui` 导入，预览显示该变量。
- 引用示例用中性的说法：「在上面的示例中，……」。
- 示例中的代码应能运行。写完后照页面实际运行一遍。

## 提示框

```md
::: tip
补充说明，不读不影响理解正文。
:::

::: warning
容易出错的地方：后果与避免方法。
:::

::: details 标题
可跳过的深入说明。
:::
```

## 格式

- 中文与英文、数字之间加空格；代码、文件名、API 名用反引号。
- 真机测试得出的规则，注明来源并链接到[真机规则](reference/rules.md)。
- 前置知识（JavaScript、附加包结构）不在正文展开，链接到外部资料。

## 术语

| 使用 | 不使用 |
|---|---|
| 控件（JSON UI 中的一个元素） | 元件 |
| 组件（继承内置类编写的可复用部件） | 控件 |
| 界面（挂载到一个服务端表单上的整棵树） | 屏幕 |
| 页面（界面文件 `pages` 中的一页，服务端切换） | 页、翻页 |
| 选项卡（`Tabs`，客户端切换） | 分页、标签页 |
| 服务端表单（`ActionFormData`） | 原生表单 |
| 行为包、资源包、附加包 | BP、RP、addon |
| 真机 | 实机、游戏内 |

## 首页

网站首页不由 Markdown 生成，源文件在 `docs/site/home/`：`index.html`（文字与结构）、`home.css`（游戏风格的样式）、`shop.screen.mjs`（首页上真实运行、并原样展示的商店界面）。手册目录 `index.md` 生成为 `contents.html`。

- 首页的数字（真机规则、静态检查、在线示例）在构建网站时统计，不要手写。
- 首页与手册各页的标题、侧栏、按钮用 GNU Unifont 的子集（`docs/site/fonts/unifont-site.woff2`，SIL OFL 1.1）。改了标题、侧栏或首页的文字后运行 `python3 scripts/subset-site-font.py`（需要 `pip install fonttools brotli`）重新裁剪；构建网站时若有子集中没有的字，会给出提示。
- 素材都是自己画的；不使用原版贴图（仓库是 MIT 许可，Mojang 的素材无法随之授权）。可以使用游戏截图。
