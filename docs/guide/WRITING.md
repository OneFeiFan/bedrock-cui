# 手册写作约定

以 [Vue 中文文档](https://cn.vuejs.org/guide/introduction) 的笔调为准，编排参考 [react.dev](https://react.dev/learn)。拿不准时，对照 Vue 中文文档里对应主题的页面。

## 结构

- **指南**（`guide/`）按章节递进，后一页只用到前面介绍过的内容。只介绍常用用法，完整的选项链接到参考。
- **参考**（`reference/`）按模块逐条列出 API：签名、参数、返回值、示例，不讲背景。

一页的结构：

```md
# 标题

一句话说明本节的内容（可省略）。

## 小节标题

概念说明 → 示例代码 → 对示例的说明。

## 下一步（只在入门部分使用）
```

## 笔调

主语是 API、框架或游戏，不是读者：

| 不这样写 | 这样写 |
|---|---|
| 你可以用 `Paragraph` 让文字按宽度折行。 | `Paragraph` 按给定的宽度折行。 |
| 你会注意到两件事。 | 上面的示例展示了两点。 |
| 这一页带你从空文件夹走到…… | 本节演示从创建项目到……的流程。 |
| 点一下箭头，表单会关掉。 | 点击箭头时，表单关闭。 |
| 给控件起名字是个好习惯。 | 建议为需要定位的控件设置名称。 |
| 直接写 JSON UI 是一件费劲的事。 | （删去。只陈述框架做什么。） |

- 「你」只用于指示和建议：「你不应在……时……」「应提交到版本库」。
- 不写关于文档本身的话（「下面马上会用到」「你已经学会了」），不评价、不安慰、不推销（「强大」「轻松」「逐像素」「好消息是」）。
- 用书面语：「此」「该」「将」「即」「可」；不用「就是」「其实」「当然」「一下」「啦」。
- 机制用技术语言讲清楚：「游戏在同一层内按材质分批绘制，先在控件树中出现的批次先绘制。」
- 能写进代码注释的说明，写在注释里。
- 标题用名词短语：「挂载到服务端表单」「服务端翻页」「静态检查」，不用「读懂检查的提示」这类对读者说的话。
- 加粗只用于列表项开头的术语，正文里不加粗。

## 示例

- 示例只包含说明当前主题所需的代码，省略的部分写 `// ……`。
- 改动已有代码时，用 ` ```js {3-4} ` 标出改动的行。
- 引用示例用中性的说法：「在上面的示例中，……」。
- 示例中的代码应能运行。写完后照页面实际运行一遍。

## 提示框

```md
::: tip
补充说明，不读不影响理解正文。
:::

::: warning
容易出错的地方：后果与避免方法。
:::

::: details 标题
可跳过的深入说明。
:::
```

## 格式

- 中文与英文、数字之间加空格；代码、文件名、API 名用反引号。
- 真机测试得出的规则，注明来源并链接到[真机规则](reference/rules.md)。
- 前置知识（JavaScript、附加包结构）不在正文展开，链接到外部资料。

## 术语

| 使用 | 不使用 |
|---|---|
| 控件（JSON UI 中的一个元素） | 元件 |
| 组件（继承内置类编写的可复用部件） | 控件 |
| 界面（挂载到一个服务端表单上的整棵树） | 屏幕 |
| 页（`Pages` 中的一页） | 页面 |
| 服务端表单（`ActionFormData`） | 原生表单 |
| 行为包、资源包、附加包 | BP、RP、addon |
| 真机 | 实机、游戏内 |
