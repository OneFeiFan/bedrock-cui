# 脚本端的性能

## QuickJS

行为包脚本在 QuickJS 中解释执行，没有即时编译。用 quickjs-emscripten 实测，同样的计算比 Node（V8）慢十倍左右。在 Node 中耗时 20 毫秒的函数，在游戏中可能需要 200 毫秒以上；一个游戏刻为 50 毫秒。

服务端表单的打开在脚本计算完成之后进行。打开或翻页时的计算耗时较长，表现为界面延迟出现或翻页时界面消失一段时间。

## softWrap 的开销

`softWrap()`（用法见[文字 · 运行期文字](text.md#运行期文字)）需要多次模拟游戏的折行，一次模拟约 0.65 毫秒（QuickJS）。默认的 `'fast'` 方式通常模拟十几次，单次调用约 13 到 23 毫秒；结果按文字与宽度缓存，内容不变时再次调用几乎没有开销。

翻页时，若运行期文字的内容不变（例如玩家背包没有变化），`softWrap()` 直接返回缓存的结果。

## 建议

- 在 `computed` 与方法中只做显示所需的计算：每次打开或重新打开界面，`computed` 都会重新计算。
- 内容不变的文字，在脚本中保存计算结果，不要每次打开表单时重新生成。
- 页面跳转、点击按钮的过程中不要向聊天栏发送消息，原因见[页面](pages.md#注意)。

## 测量方法

脚本的耗时可以在本机用 [quickjs-emscripten](https://github.com/justjake/quickjs-emscripten) 测量：将脚本打包为单个文件（例如用 rolldown 输出 IIFE 格式），在 QuickJS 上下文中执行并计时。结果比 Node 中的测量更接近游戏中的实际耗时。
