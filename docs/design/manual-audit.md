# 手册审计计划（2026-11-21）

## 一、起因：用户抽查发现的问题

| 位置 | 问题 | 根源 |
|---|---|---|
| 跨平台 · 框架中的处理 | `paginate()` 像凭空出现：公开接口，正文从未介绍，只在跨平台、滚动两页顺带提到 | API 没有「归属页」；提到它的地方不链接、不介绍 |
| 浏览器预览 · 预览的数据 | 「界面文件的界面，预览中的数据就是……」不通；一节里混着数据、屏幕尺寸与贴图 | 句子未通读；一节多个主题 |
| 浏览器预览 · 在网页中嵌入预览 | 示例导入早已不存在的 `buildBook`（`./ui/book.mjs`，统一页面写法之前）；正文的 `title`、`formText`、`formButtons` 三个信号在示例中没有出现、也没有解释 | 示例过时；正文与示例对不上 |
| 脚本端 · 放入行为包 | 整节不知所云：没说读者为什么要关心（新建项目由 sapdon 自动打包），脚本大小与「不用 sapdon 时」两件事挤在一个标题下 | 一节缺少「何时需要」的开场；一节多个主题 |
| 脚本端 · softWrap | 「第三个参数为选项」：没说明是对象，没有示例 | 参数的形态没讲清 |
| 多章 | 运行期文字的处理分散在「文字」「脚本端」「跨平台」「性能」四章；`wrapText`、`softWrapText`、`textWidth` 无处介绍 | 主题没有唯一的归属页 |

共同的根源：**检查不成体系**——此前的审计按关键词搜索已知的旧写法，抽读部分页面，没有逐页、逐节地核对「每个名词是否先介绍」「正文与示例是否一致」「一个主题是否只在一处讲完」。

## 二、方法

### 取舍：手册只写开发者用得上的内容（用户，2026-11-21）

手册服务开发者，不是把框架完整介绍一遍；内容不是越多越好。

| 保留 | 删除或缩减 |
|---|---|
| 开发者要做的事（写界面、传数据、打包） | 框架的实现细节（内部模块、数据的编码方式） |
| 开发者会遇到的行为（游戏中的限制、会出错的写法） | 测量方法、调试过程 |
| 开发者要做的选择（Router 还是 Tabs） | 用不到的底层函数、常量与类型（正文不写，API 参考也不列） |
| | 测试包的版本号与实验的行号：写「真机」即可，细节留在设计文档 |

逐页检查时，每一段先问：开发者做事时用得上吗？用不上就删。

### 自动检查（scripts/audit-docs.mjs，新写）

1. **公开接口的覆盖**：各公开入口（`bedrock-cui`、`/runtime`、`/node`、`/web`、`/dom`）导出的名字，在指南正文中有没有「归属页」（在标题、表格首列或示例的导入中出现）；只在参考中出现的列出来，逐个决定是否需要在指南中介绍。
2. **未介绍就提到**：某页提到一个接口，而这一页既不是它的归属页、同一段中也没有链接到归属页。
3. **措辞**：「A 的 A」类的叠词结构、「视图」等旧术语、「表单」与「界面」的混用。

### 逐页检查（按侧栏顺序，每页一份记录）

- **开场**：第一段说明本页讲什么；每一节开头说明读者什么时候需要它（尤其是「不需要也行」的内容）。
- **名词**：每个接口、选项、术语，在本页介绍，或链接到归属页；读者按侧栏顺序阅读时，用到的概念已经出现过。
- **一节一个主题**：标题与内容一致。
- **示例**：使用当前的写法；能运行；正文提到的东西示例里有（或不提）；参数的形态（对象、数组）在示例中写出来；有界面效果的给预览。
- **句子**：通读；没有不通、歧义的句子。
- **事实**：与源码、真机规则一致。

### 跨页检查

- **主题归属表**（下文）：每个主题只在归属页讲完，其他页一句话加链接。
- **术语**：同一事物同一名称（页面 / 界面 / 表单；页面组 / Router；跳转元素）。
- **阅读顺序**：侧栏顺序中，后文用到的概念在前文介绍过，或有链接。

## 五、记录

### 第 1 步：抽查到的问题（已修）

- 运行期文字归并到「文字 · 运行期文字」：softWrap（第三个参数说明为对象并示范）、wrapText / preWrap / paginate（对比表与可运行的示例）、autoSpace / textWidth / measureText。`bedrock-cui/runtime` 补上 `paginate` 的导出（此前只在主入口，脚本处理文字要从两个入口导入）。
- 脚本端：「放入行为包」拆为「脚本的大小」（开场说明新建项目已自动打包）与「不使用 sapdon 时」；softWrap 一节改为链接。
- 浏览器预览：「预览的数据」改为「预览的数据与设置」并改写首句；「在网页中嵌入预览」重写——只显示控件树用 mountPreview，界面文件两个函数一起用，讲清三个信号的作用（runScreenInBrowser 写入、mountPreview 显示），删去过时的 buildBook。
- 跨平台、性能、滚动：提到运行期文字处链接到归属页。

### 第 2 步：自动检查（scripts/audit-docs.mjs，npm run docs:audit）

- 第一版的「归属页」靠推断（标题、表格首列、示例导入），噪音太大；第二版只认标题与组件页的 API 表，并按侧栏顺序判断「读到之前就提到」，仍把组件页（侧栏末尾）与值类型（Color、Size 等，在「尺寸与位置」等章节中介绍但标题中没有名字）算成没有归属。
- 下一步：改为人工维护的归属表（名字 → 归属页），脚本按表检查；公开接口中 84 个没有归属页，其中多数是排版引擎、表达式、信号的底层函数与常量，需逐个决定：在指南中介绍、只留参考，或移出公开入口（后者是不兼容的改动，须用户同意）。
